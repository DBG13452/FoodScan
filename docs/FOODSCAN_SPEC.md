## Продукт и данные

FoodScan анализирует пищевые продукты по штрихкоду: сканирование и ручной ввод,
состав и КБЖУ, аллергены и добавки, объяснимая персонализированная оценка,
альтернативы, избранное, история, кеш и просмотр ранее загруженных продуктов офлайн.
Регистрация и аккаунты в MVP отсутствуют.

На первых этапах используются локальные демонстрационные продукты.
Подключение Open Food Facts обязательно на этапе 6. Android обращается к API по
HTTPS напрямую; собственный сервер не нужен. FastAPI, Node.js backend, PostgreSQL,
собственный облачный API, обязательный Firebase и Docker требуют отдельного согласования.

Для API использовать актуальную официальную документацию, получение продукта по
штрихкоду, идентифицирующий User-Agent и минимальный набор запросов. Соблюдать
опубликованные лимиты; обрабатывать 404, 429, серверные ошибки, отсутствие сети,
таймауты. Не запрашивать API на каждом кадре камеры. Кешировать данные и показывать
источник. Open Food Facts наполняется пользователями: сведения могут быть неполными
или ошибочными. Неизвестное значение не равно нулю; данные нельзя выдумывать.

CameraX и ML Kit: EAN-13, EAN-8, UPC-A, UPC-E, разрешения камеры, ручной ввод,
защита от повторных срабатываний. Retrofit/OkHttp и совместимый JSON-парсер — на
этапе API; Coroutines, StateFlow и ViewModel — по необходимости.
Room — избранное, история и кеш; DataStore — настройки и выбранный сценарий.
Предусмотреть удаление пользовательских данных и определить политику Auto Backup.

## Персонализация и оценка

Независимый от UI `ScoringEngine`: детерминированная оценка 0–100, объяснения
положительных и отрицательных факторов, сопоставимые данные на 100 г или 100 мл,
учёт категории, корректная обработка неполных данных. При недостатке данных —
«Недостаточно данных для оценки». Перед реализацией методику согласовать с пользователем;
не вводить необъяснённые научные коэффициенты. FoodScan Score, Nutri-Score и NOVA
показывать отдельно.

| Сценарий | Учитываемые особенности |
| --- | --- |
| NORMAL | Общий пищевой профиль |
| SPORT | Белок, калорийность, сахар, насыщенные жиры и общий профиль; белок сам по себе не гарантирует высокую оценку |
| WEIGHT_CONTROL | Калорийность, белок, волокна, сахар, насыщенные жиры |
| SUGAR_CONTROL | Сахар, углеводы, волокна и другие доступные показатели |

Смена сценария пересчитывает оценку, не изменяя исходные сведения о продукте.
FoodScan — информационный сервис: никаких диагнозов, лечения, гарантий безопасности,
снижения веса или безопасности при диабете. E-код сам по себе не означает вред.
Для добавок показывать код, название, назначение, описание и источник; неизвестные
добавки обрабатывать явно. Альтернативы сравнивать в сопоставимой категории с
учётом сценария и пояснением преимуществ. Если надёжный подбор невозможен,
согласовать ограниченную реализацию.

## Экраны

- Главная: FoodScan, сценарий, большая кнопка сканирования, последние продукты,
  избранное, нижняя навигация.
- Сканер: камера и рамка, ручной ввод, разрешения, загрузка и ошибки.
- Продукт: фото, название, производитель, штрихкод, оценка и объяснения, сценарий,
  калории, белки, жиры, углеводы, сахар, соль, насыщенные жиры, волокна, состав,
  аллергены, добавки, источник, избранное и альтернативы. Отсутствующие поля — явно.
- Добавки: описание и источник. Альтернативы: сравнение и состояние отсутствия результатов.
- Избранное: добавление, удаление, список, открытие продукта.
- История: дата и время, список, открытие продукта, удаление записи, очистка.
- Настройки: сценарий, управление историей, источники, дисклеймер, сведения о приложении.
