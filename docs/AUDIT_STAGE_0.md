# FoodScan — состояние проекта и план разработки

Дата проверки: 10 октября 2026 года.

## Итог

FoodScan находится на стадии стартового Android-проекта на Kotlin и Jetpack Compose. Реализован только шаблонный экран `Hello Android!`. Debug APK собран, существующий локальный тест прошёл, Android Lint завершился успешно с предупреждениями. Пользовательские сценарии FoodScan пока отсутствуют.

Во время аудита исходный код, ресурсы и конфигурация сборки не изменялись. Создан только этот документ; запуск Gradle также обновил служебные кэши, отчёты и артефакты сборки. Серверная часть не создавалась и не входит в предлагаемый план. Реализация плана начинается только после подтверждения пользователя.

## Реализованное поведение

- Одна launcher Activity: `MainActivity`, `exported=true`, стандартный MAIN/LAUNCHER intent filter.
- Compose `Scaffold`, отступы системных областей, вызов `enableEdgeToEdge()` и `Greeting`.
- Светлая и тёмная Material 3 тема, динамические цвета при соответствующей версии Android, стандартная типографика.
- Имя приложения `FoodScan`, шаблонные launcher-иконки и Compose preview.
- В manifest разрешены backup и RTL, установлены шаблонные правила резервного копирования и `adjustResize`.
- Разрешения камеры и доступа в Интернет не объявлены.

Сканирование штрихкода, OCR, распознавание еды по фотографии, навигация, модель продукта, ViewModel, хранилище, история, поиск и интеграции с источниками данных отсутствуют. Требования к конкретному способу сканирования пока не заданы; название FoodScan само по себе их не определяет.

## Результаты проверок

1. `gradlew.bat --offline --version` — успешно после предоставления доступа к пользовательскому кэшу Gradle; подтверждены Gradle `9.6.0` и JVM `25.0.3`.
2. Первая попытка `--offline :app:assembleDebug :app:testDebugUnitTest :app:lintDebug` завершилась ошибкой: в кэше отсутствовал `com.android.tools.lint:lint-gradle:32.4.1`. Сообщение о сохранении configuration cache сопровождало эту ошибку разрешения зависимости и само по себе не доказывает несовместимость configuration cache.
3. Повторный запуск без `--offline` загрузил недостающие зависимости. Задачи `:app:assembleDebug` и `:app:testDebugUnitTest` завершились; общий запуск был прерван перезапуском среды до получения итогового результата Lint.
4. Debug APK существует: `app/build/outputs/apk/debug/app-debug.apk`.
5. XML-отчёт `app/build/test-results/testDebugUnitTest/TEST-com.foodscan.app.ExampleUnitTest.xml` подтверждает: 1 тест, 0 ошибок, 0 падений, 0 пропусков. Тест проверяет только `2 + 2 = 4`, продуктового покрытия нет.
6. Повторный `gradlew.bat :app:lintDebug --console=plain` — `BUILD SUCCESSFUL`, configuration cache сохранён. SARIF-отчёт содержит 15 предупреждений: 6 `GradleDependency`, 1 `NewerVersionAvailable`, 1 `RedundantLabel` и 7 `UnusedResources`. Это уведомления о версиях зависимостей, повторении label Activity и неиспользуемых XML-цветах; исправления в рамках аудита не выполнялись. Отчёты: `app/build/reports/lint-results-debug.html` и `app/build/reports/lint-results-debug.sarif`. Уведомления Lint о версиях не заменяют отдельную проверку совместимости перед обновлением.

Instrumented-тест проверяет только package name. Он не запускался. Установка APK, запуск на устройстве/эмуляторе, ручная проверка UI, release-сборка и релизная подпись не проверялись. Успех debug-сборки не означает готовность к публикации.

## Вопросы и ограничения для следующего этапа

- Определить назначение сканирования: штрихкод продукта, текст этикетки или фотография еды. Предлагаемый ниже MVP условно ориентирован на штрихкод; это предложение, требующее подтверждения.
- Согласовать состав карточки: название, состав, пищевая ценность, аллергены и источник сведений. Не вводить оценку «полезности» без согласованной методики.
- Выбрать режим данных: локальный демонстрационный набор для первого MVP; подключение существующего внешнего API возможно только как отдельное согласованное расширение. Собственный сервер не требуется.
- Проверить необходимость обновления зависимостей при расширении функциональности. Аудит не включает массовое обновление версий; текущая debug-сборка работает.
- Перед сохранением пользовательских данных определить правила backup и удаления истории: текущие правила шаблонные.
- Подготовить контроль версий перед реализацией по согласованию; сейчас история изменений отсутствует.

## Поэтапный план — предложение для подтверждения

| Этап | Работы | Критерий завершения |
| --- | --- | --- |
| 1. Согласование MVP | Утвердить способ сканирования, поля карточки, локальный источник данных и необходимость истории. Зафиксировать сценарии и ограничения. | Согласован короткий перечень функций и экранов. |
| 2. Основа интерфейса | Заменить Greeting на главный экран; добавить переходы между сканированием, карточкой и историей, если она входит в MVP. Организовать состояние экрана и доступ к данным без преждевременного дробления на модули. | Основной сценарий проходит на демонстрационных данных; есть пустые состояния и сообщения об ошибках. |
| 3. Сканирование | Для варианта со штрихкодом добавить камеру, запрос разрешения и распознавание кода. Обработать отказ, повторные срабатывания и возврат на экран; предусмотреть ручной ввод. Для OCR/фото состав работ пересмотреть после этапа 1. | Реальный код считывается на устройстве; отказ в разрешении не блокирует ручной ввод. |
| 4. Карточка продукта | Связать код с локальным набором продуктов; показывать согласованные поля, отсутствие продукта и неполные данные. Отделить источник данных от UI для возможного дальнейшего подключения существующего API. | Известный код открывает карточку; неизвестный даёт понятное состояние без выдуманных сведений. |
| 5. Локальная история | Если подтверждена: сохранять просмотры/сканирования на устройстве, добавить просмотр и удаление; определить backup. | История сохраняется после перезапуска и удаляется пользователем. |
| 6. Проверка MVP | Добавить содержательные тесты обработки кода и состояния экрана, проверить разрешения, жизненный цикл, темы, большие шрифты и доступность. Выполнить debug-сборку, unit-тесты и Lint; проверить release-сборку отдельно. | Согласованные сценарии проходят, ошибки устранены, ограничения записаны. |

Этапы 2–6 не начаты. До подтверждения пользователя работа ограничивается аудитом и этим документом. Серверная часть, облачное хранение и авторизация не входят в план.
