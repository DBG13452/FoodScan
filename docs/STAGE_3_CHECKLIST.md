# Этап 3 — запуск и проверка на Android Emulator

Это инструкция для ручной проверки. Она не является отчётом о выполненных UI-тестах.
Результаты автоматической сборки и Lint находятся в [PROJECT_STATUS.md](../PROJECT_STATUS.md).

## Запуск

1. В Android Studio открыть существующий проект `C:\Projects\FoodScan`.
2. Выполнить **File → Sync Project with Gradle Files** и дождаться завершения.
   При первой синхронизации нужен интернет для Navigation Compose и его зависимостей.
3. Открыть **Tools → Device Manager** и запустить **Medium Phone API 36.1** кнопкой ▶.
   Дождаться полной загрузки Android. API 36.1 подходит: minSdk приложения — 26.
4. В верхней панели выбрать конфигурацию **app** и запущенный эмулятор.
5. Нажать **Run ▶** или **Shift+F10**. Android Studio соберёт и установит debug APK.
6. Дождаться FoodScan. Вместо Hello Android должны появиться название, сценарий
   «Обычное питание · NORMAL», большая кнопка сканирования и нижняя панель.

Альтернативная установка уже собранного APK из PowerShell:

```powershell
& "$env:LOCALAPPDATA\Android\Sdk\platform-tools\adb.exe" install -r .\app\build\outputs\apk\debug\app-debug.apk
& "$env:LOCALAPPDATA\Android\Sdk\platform-tools\adb.exe" shell am start -n com.foodscan.app/.MainActivity
```

Команды предполагают ровно один подключённый эмулятор/телефон и стандартный путь SDK.
Если устройств несколько, добавить `-s <serial>` после `adb.exe`.

## Сценарии проверки

| Действие | Ожидаемый результат |
| --- | --- |
| Запуск приложения | Главная вкладка выбрана; виден FoodScan и сценарий NORMAL |
| «Сканировать продукт» | Открывается «Сканирование продуктов» с пояснением; камера и запрос разрешения не появляются |
| «На главную» из сканирования | Возврат на главную; нижняя панель отражает переход |
| Нажатие каждой из четырёх нижних вкладок | Открывается соответствующий экран, выбранная вкладка подсвечивается |
| Повторное нажатие выбранной вкладки | Экран не дублируется в стеке |
| Несколько переключений вкладок, затем системная «Назад» | Возврат на главную без перебора всех ранее нажатых вкладок |
| Системная «Назад» на главной | Обычный выход/сворачивание Activity средствами Android |
| «Открыть профиль» на главной | Профиль со сценарием NORMAL, объяснением недоступных настроек и информацией о сервисе |
| Прокрутка главной | Видны овсяные хлопья, натуральный йогурт и цельнозерновой хлеб; у всех отметка «Демо-продукт» |
| «Перейти в избранное» под списком | Пустое состояние избранного и рабочая кнопка возврата |
| Прокрутка главной, переход в другой раздел, возврат | Позиция прокрутки восстанавливается |
| Поворот эмулятора, затем обратно | Текущая вкладка сохраняется; содержимое прокручивается и не заходит под системные панели |
| Перевод ОС в тёмный режим | FoodScan сохраняет фирменную светлую тему; системные значки остаются читаемыми |

Не нажимать на карточки примеров в ожидании деталей: пока это информационные блоки
без действия, настоящая карточка продукта относится к этапу 4.

## Шрифт и Preview

1. В настройках Android увеличить размер шрифта (**Display → Display size and text**;
   название пункта зависит от языка системы) и вернуться в FoodScan.
2. Проверить перенос длинных подписей, доступность всех четырёх вкладок, прокрутку
   главной до конца и отсутствие перекрытия нижней панелью.
3. После проверки вернуть удобный системный размер шрифта.
4. В Android Studio открыть `HomeScreen.kt` → **Split/Design → Build & Refresh**.
   Предусмотрены телефон, экран 320 dp со шрифтом 200%, планшет и пустой список.
5. В `FoodScanApp.kt` проверить Preview главной с нижней навигацией, включая 200%.
   Для переходов и прокрутки использовать Interactive Preview или эмулятор.

## Что работает и что пока демонстрируется

Работают переходы через Navigation Compose, кнопки переходов, нижние вкладки,
системный возврат и отображение локальных демонстрационных элементов.
Навигация и scroll-state используют механизмы сохранения Compose, без базы данных.

Сканирование и ручной ввод, сохранение избранного и истории, изменение сценария,
реальные продукты, фотографии, FoodScan Score и карточка продукта пока не реализованы.
NORMAL фиксирован; три примера не являются результатом сканирования или реальной
историей. Кнопок с имитацией успешного сохранения/сканирования нет.

## Архитектура

`MainActivity → FoodScanTheme → FoodScanApp (Scaffold + NavigationBar) → FoodScanNavHost`.
Четыре маршрута описаны в `navigation/FoodScanDestination.kt`.
Экранные composable находятся в `ui/home`, `ui/scanner`, `ui/favorites`, `ui/profile`;
экраны получают callbacks, а NavController остаётся в слое навигации.
Это позволяет отдельно показывать главную в Preview и позже подключать данные.

Для переходов верхнего уровня применяются `launchSingleTop`, `popUpTo` с `saveState`
и `restoreState`. Нажатие текущей вкладки пропускается. Реальная проверка поведения
на устройстве выполняется по таблице выше.

Добавлена одна прямая зависимость: `androidx.navigation:navigation-compose:2.9.8`.
Выбран исправленный релиз ветки 2.9; переход на ветку 2.10 для четырёх простых
маршрутов не требуется. Источник: [официальные release notes Navigation](https://developer.android.com/jetpack/androidx/releases/navigation#2.9.8).
Версии остальных прямых зависимостей сохранены; Gradle может повысить разрешённые
транзитивные версии по требованиям Navigation. Дополнительные плагины сериализации,
Navigation Testing и библиотека иконок не нужны: маршруты фиксированы, иконки локальные vector drawable.
