# FoodScan

Учебное Android-приложение для анализа пищевых продуктов по штрихкоду.
Package: `com.foodscan.app`. Kotlin, Jetpack Compose, Material 3.

Текущий результат — этапы 7–12: реальная карточка, оценка, добавки, избранное, история и сценарии.
Сканирование или ввод штрихкода открывает пищевую ценность, состав, аллергены, добавки и источник.
Неизвестные значения показаны как «Нет данных», нулевые значения сохраняются.
Главная показывает реальные последние просмотры. Три условных продукта используются только в Preview и тестах.
В блоке «Оценка продукта» — индекс FoodScan 0–100 по согласованной методике и сценарий питания.
Отдельный раздел возможных следов аллергенов, Nutri-Score и NOVA убраны из карточки.
Нижние вкладки открывают Главную, Сканер, Избранное и Профиль без анимации перехода.
Избранное и история сохраняются в Room; четыре сценария и включение истории — в DataStore.
При нехватке сведений число не рассчитывается, показываются причины. Оценка имеет объяснение вкладов.
В справочнике 148 добавок: поиск, описания влияния на организм и русскоязычные источники.
Карточка продукта показывает цветовые категории с текстовыми подписями;
неизвестные коды остаются без оценки. Зелёный не означает безопасность любой дозы.

## Сборка в Windows

Открыть существующий проект в Android Studio. Проверенная конфигурация: Gradle 9.6.0,
AGP 9.4.1, JVM Gradle 25, compileSdk/targetSdk 37, minSdk 26.
Путь Android SDK задаётся в локальном `local.properties`.

```powershell
.\gradlew.bat :app:assembleDebug :app:lintDebug --console=plain
```

При первой сборке требуется загрузка Navigation Compose и его транзитивных зависимостей.
После загрузки можно добавить `--offline` для сборки из локального кеша.

APK: `app/build/outputs/apk/debug/app-debug.apk`.
Lint: `app/build/reports/lint-results-debug.html`.

Для Preview главной открыть `HomeScreen.kt`; для главной вместе с навигацией — `FoodScanApp.kt`.
Для карточки продукта и состояний без данных — `ProductScreen.kt`.
Каталог дизайн-системы остаётся в `FoodScanDesignSystemPreview.kt`.

## Проверки

```powershell
.\gradlew.bat :app:testDebugUnitTest :app:lintDebug --console=plain
.\gradlew.bat :app:connectedDebugAndroidTest --console=plain
```

Для UI-тестов нужен подключённый разблокированный телефон или эмулятор.
По умолчанию сетевой UI-тест пропускается; для реального запроса добавить
`"-Pandroid.testInstrumentationRunnerArguments.liveApi=true"`.
Проверяются карточки всех трёх продуктов, возврат, восстановление сохранённого состояния,
неизвестный ID, нулевые и отсутствующие значения, экран 320 dp со шрифтом 200%,
а также регрессия быстрых переключений вкладок, избранное/история, сценарии и повторное
открытие файлов Room/DataStore. Тесты изолированы от пользовательского хранилища.
Тестовые снимки сохраняются в каталоге
`product-screenshots` внешних файлов приложения.

Собственный сервер не используется. Если он потребуется, бэкенд должен быть на Python.

Снимки избранного и истории доступны после перезапуска. Общий постоянный кеш произвольных
запросов и управление обновлением данных относятся к этапу 13. Альтернативы — к этапу 14.
