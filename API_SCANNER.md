# Сканер и Open Food Facts — этапы 5 и 6

## Проверить приложение

1. Открыть «Сканер» или нажать «Сканировать продукт» на главной.
2. Нажать «Включить камеру» и разрешить доступ. Навести камеру на EAN-8, EAN-13,
   UPC-A или UPC-E. После первого корректного распознавания камера остановится,
   откроется загрузка продукта. Изображения камеры не отправляются на сервер.
3. Для ручной проверки ввести `3017620422003`, нажать «Найти продукт».
   На момент разработки API вернул Nutella; наличие и содержимое записи зависят от Open Food Facts.
4. Проверить фото, бренд, штрихкод, источник, КБЖУ, состав и аллергены.
   Если перевода в базе нет, исходный текст сохраняется. Неизвестное значение — «Нет данных».
5. «Назад» со стрелкой возвращает в сканер. Для нового сканирования снова включить камеру.
   Нажатие нижней вкладки открывает её корневой экран, а не прежний продукт.
6. Без разрешения камеры ручной ввод остаётся доступен. После постоянного отказа
   кнопка ведёт в настройки приложения. При ошибке камеры можно повторить запуск.

Ошибки: неверная контрольная цифра отсекается локально; 404, 429, 5xx, таймаут,
отсутствие соединения и повреждённый JSON имеют отдельные сообщения.
Повтор выполняется пользователем. При 429 учитывается Retry-After; до истечения
паузы новый запрос не отправляется.

## Реализация

- CameraX 1.6.2: PreviewView в COMPATIBLE-режиме, привязка к lifecycle, закрытие
  ImageProxy, KEEP_ONLY_LATEST, освобождение камеры при уходе с экрана.
- ML Kit barcode-scanning 17.3.0: модель включена в APK, распознавание локальное;
  AtomicBoolean пропускает один результат за сеанс камеры. UPC-E раскрывается в UPC-A.
- Retrofit 3.0.0 / OkHttp 4.12.0 / Gson: HTTPS-запрос
  `GET https://world.openfoodfacts.org/api/v3/product/{barcode}` с `fields`, `lc=ru`,
  `product_type=food` и идентифицирующим User-Agent.
- ViewModel + StateFlow: загрузка переживает поворот, повторные нажатия не создают
  параллельных запросов, отмена coroutine сохраняется.
- Repository: общий mutex, интервал 5 секунд между сетевыми чтениями, кеш до 32 продуктов
  на 5 минут в памяти процесса. Это не постоянный офлайн-кеш и не история.
  Для неоднозначного восьмизначного ввода UPC-A проверяется только после 404 для EAN-8.
- Coil 2.7.0: фото с разрешённого HTTPS-домена Open Food Facts, загрузка/ошибка,
  штатный кеш изображений. Остальные данные доступны при ошибке фото.

Дополнительные библиотеки имеют конкретные роли: камера, распознавание, HTTP/JSON,
сохранение состояния загрузки и фото. Существующие версии остальных прямых зависимостей
не обновлялись. Новых серверов, модулей и аккаунтов нет.

## Данные

Используются только нормализованные поля `*_100g` продукта как он продаётся,
а не `*_serving`, `*_prepared` или оценённые `nutriments_estimated`.
При неизвестной базе подпись — «На 100 г или 100 мл (по данным источника)».
Пустые массивы аллергенов/добавок не доказывают их отсутствия: показывается «Нет данных».
Числа с модификатором вроде `<` пока не показываются как точные значения.
Бренд не подставляется в поле производителя. В блоке «Оценка продукта» —
согласованная оценка FoodScan v1 и сценарий питания. Nutri-Score, NOVA и отдельный раздел
возможных следов аллергенов скрыты по запросу пользователя. Полный текст состава
и раздел «Аллергены» сохраняются; извлечение следов из текста состава не выполняется.

Начиная с этапа 12, избранное и история сохраняют снимки продуктов через Room,
а сценарии — через DataStore. Подробности оценки: [SCORING_PROPOSAL.md](SCORING_PROPOSAL.md).
Общий постоянный офлайн-кеш запросов остаётся отдельной работой этапа 13.

В карточке есть ссылка на исходный продукт, атрибуция Open Food Facts и лицензий.
Для учебной сборки User-Agent содержит название, версию и Android package;
перед публичным распространением в него следует добавить реальный контакт проекта.
Контактные данные не выдумывались, формы регистрации использования API не отправлялись.

## Проверки

```powershell
.\gradlew.bat :app:assembleDebug :app:testDebugUnitTest :app:lintDebug --console=plain
.\gradlew.bat :app:connectedDebugAndroidTest --console=plain
```

Проверка с одним реальным запросом и открытием продукта (телефон должен быть разблокирован):

```powershell
.\gradlew.bat :app:connectedDebugAndroidTest "-Pandroid.testInstrumentationRunnerArguments.liveApi=true" --console=plain
```

Без флага liveApi сетевой UI-тест пропускается. Остальные тесты используют
MockWebServer или локальные данные. ML Kit проверяется на сгенерированном EAN-13;
это не заменяет физическую проверку камеры на упаковке.

Выполнено 15.10.2026: 13 unit-тестов, 9 instrumented-тестов на TECNO CH6n / Android 12,
debug-сборка и Lint без ошибок. Физическая упаковка и ручной отказ в разрешении камеры
ещё не проверены. Gradle может удалять тестовую установку вместе со снимками после прогона;
снимки для визуального осмотра сохранены отдельным прямым запуском instrumentation в `build/qa`.

## Серверная часть

Android обращается к Open Food Facts напрямую. Собственный бэкенд сейчас не нужен.
**Если появится необходимость в отдельном бэкенде, по требованию пользователя он
должен быть реализован на Python.**
